### BcsOzon采集学习点 (BcsOzon Collection Learning)
- 时间 (Time): 2026-07-08
- 观察 (Observation): 成熟插件采集详细，不是靠单次页面点击，而是靠 `结构化采集系统 (Structured Collection System)`。
- 学习 (Learning): 采集结果应沉淀为 `采集契约 (Collection Contract)`、`证据包 (Evidence Pack)`、`字段解析器 (Field Parser)` 和 `上架契约 (Listing Contract)`。
- 边界 (Boundary): Ozon V2 后续按阶段补契约和字段，不一次性堆大功能，避免臃肿。
- 待拆解 (To Analyze): “通过链接上架 (List By Link)”本质应拆成 `链接识别 (Link Resolve)`、`源商品采集 (Source Collect)`、`字段映射 (Field Mapping)`、`图片处理 (Image Handling)`、`库存价格策略 (Stock And Price Policy)`、`发布到用户店铺 (Publish To Seller Store)`。

- 发布 (Publish): 上架动作可能通过 Ozon Seller 后台 Web 接口或 Seller API 以用户登录态提交；速度快的原因是本地/后台批量生成 payload 后一次性提交，而不是逐字段人工式填表。

### Superpowers架构用途 (Superpowers Architecture Use)
- 时间 (Time): 2026-07-08
- 观察 (Observation): 本地 `superpowers` 插件主要提供 `头脑风暴 (Brainstorming)`、`写计划 (Writing Plans)`、`测试驱动开发 (Test-Driven Development)`、`代码审查 (Code Review)` 等开发流程技能。
- 结论 (Conclusion): `Superpowers` 对 Ozon V2 架构设计有用，但只适合约束开发过程，不能作为生产运行期的权限锁。
- 用法 (Usage): Ozon V2 架构阶段可采用 `先设计后实现 (Design Before Implementation)`、`设计文档 (Design Spec)`、`实施计划 (Implementation Plan)`、`审查门禁 (Review Gate)`，避免边写边改导致架构漂移。
- 边界 (Boundary): 生产运行期仍必须依赖 `工具台 (Workbench)`、`后端状态机 (Backend State Machine)`、`权限隔离 (Permission Isolation)` 和 `不可跳过证据 (Mandatory Evidence)` 来防止绕路径。
