# Ozon V2 完整使用流程

## 产品边界

工作台负责商品事实和上架草稿；图片在商品建成后由独立生图任务处理。

工作台阶段：

1. 店铺商品去重与种子选择。
2. Ozon 原商品证据采集。
3. 1688 供应商和真实 SKU/主体确认。
4. 采购成本、包装尺寸、重量和建议售价确认。
5. 类目模板、必填属性、俄文内容和字典值准备。
6. 用户逐商品预览并确认提交 Ozon。
7. Seller API 接受建品后写出独立图片任务包。

图片阶段：

1. 用户先提供并保存可公网访问的 Cloudflare R2 HTTPS 通道地址。
2. 生图总控真实校验 R2 bucket 后，才从固定任务箱领取已建商品。
3. 十个固定可见任务槽位按顺序复用，最多并发十件商品。
4. 每件商品生成和验收八张 3:4 图片。
5. 图片 Skill 用八张验收图本地合成一段 3:4 滚动视频，并从 `main_01` 生成视频封面。
6. 图片 Skill 通过 R2 发布图片、视频和封面，直接更新对应 Ozon 商品，不把媒体文件回传工作台。

## 1. 启动前检查

1. 双击桌面“`Ozon V2 工具台`”。
2. 确认工具台服务、Edge 扩展和店铺授权均为绿色。
3. 只保留一个已加载的项目扩展。
4. 需要采集时，保持扩展管理的 Ozon/1688 标签页可用。

## 2. 创建批次并采集 Ozon

在“批次总览”创建目标数量。自动流程先执行店铺去重，再按批次种子采集 Ozon。

采集进度以已持久化结果为准：

- 成功：证据已写入批次。
- 最终失败：已用尽该商品的安全重试。
- 已替换：原种子被替代。
- 待处理：尚未得到终态。

进度条不等于浏览器瞬时事件；刷新后仍应从持久化结果恢复。

## 3. 选择供应商与真实 SKU

在“采集审核”逐商品处理：

1. 打开 1688 商品页核对商品。
2. 自动采集失败时，使用页面上的人工采集/重新采集入口。
3. 多 SKU 商品按 Ozon 目标颜色、尺寸、套装和数量选择真实 1688 SKU。
4. 页面唯一 SKU 可点击“单一 SKU，直接锁定主体”。
5. 确认主体证据图、可见数量和真实套装组成。

价格不参与 SKU 是否为同一主体的判定。采购价和国内运费在后续价格区由用户确认。

没有合格供应商时，只阻塞当前商品；其他商品继续。可稍后补采或替换该商品，不能让整个批次宕机。

## 4. 价格与包装证据

工作台会先按真实证据预填可确认项：

- 已锁定 1688 SKU 的人民币价格。
- 1688 页面明确采集到的国内运费或包邮事实。
- 1688 锁定商品明确标注的包装重量和包装尺寸。
- 1688 没有包装数据时，可回退使用 Ozon 原商品明确标注的包装重量和包装尺寸。

普通商品净重、商品本体尺寸和无法解析的配送文字不会冒充包装证据。页面会标明每个预填值的来源；用户仍需核对、补齐空白项并确认：

- 采购价（人民币）。
- 国内运费（人民币）。
- 包装重量（克）。
- 包装长、宽、高（厘米）。
- 目标净利润率。

工作台使用固定 GUOO 陆空物流公式和店铺参数计算：

- 跨境运费。
- 总成本。
- 未取整售价。
- 建议人民币售价。
- Ozon 卢布上架价。
- 划线价。

用户确认后，包装长宽高和重量同时成为后续属性字段证据。原始 1688 链接保留，便于回看供应商事实。

## 5. 字段草稿

工作台先完成确定性映射：

- 原产国固定为中国。
- 无真实品牌时使用 Ozon 认可的“无品牌”值。
- 单商品工作流默认不与其他商品卡合并。
- 卖家编码、包装数据和锁定 SKU 数量由工作台生成。
- 完整结构化 Ozon 属性继续作为俄文术语和非身份客观事实证据。
- 1688 锁定 SKU 和供应商属性优先决定商品身份。

然后复制工作台中的整批字段命令，在 Codex 中使用：

```text
$ozon-intelligent-field-drafter
```

字段 Skill 必须：

1. 读取全部 `pending` 字段任务。
2. 核对 `candidate_evidence_refs` 和完整 `evidence_index`。
3. 把真实中文商品事实翻译为自然俄文。
4. 删除“现货当天发、包邮、一件代发”等供应商履约/促销话术。
5. 仅从锁定 1688 原图判断允许的视觉字段。
6. 无证据的质检、认证、海关、保修、精确尺寸等事实必须标记缺口，不得猜测。
7. 持续处理到 `pending=0`，并分别报告 ready、gap 和 blocked 商品。

`pending=0` 仅表示每个字段已有决策，不代表全部商品可上传。必填字段缺口仍会阻塞对应商品。

## 6. 必填补录、预览与提交

上传页按商品独立门禁：

- 类目模板。
- 必填属性。
- 俄文原创/规范化内容。
- 一张已锁定的公开 1688 原图。
- 已确认价格和包装证据。
- Seller API 精确字典值。

工作台只对当前类目模板中仍然缺失的必填字段显示“补充缺失必填字段”输入区。用户填写并保存后，值作为独立的用户确认事实证据保存，工作台立即重算该商品门禁；可选字段不要求用户逐项填写。

已经通过门禁的商品可以先上传，不等待其他阻塞商品：

- 单件精细处理：点击预览只生成本地 Seller API 请求预览；点击确认上传才提交该商品。
- 批量处理：点击“批量校验并上传可用商品”，一次确认后以最多四件并发分别校验和提交。每件商品拥有独立 Seller API 任务，一件失败不会拖住其他商品。
- 发现必填字段明显不适用于当前商品时，工作台先自动刷新该商品的 Seller API 类目模板，不把错误类目的字段交给用户硬填。

初次建品只使用一张已锁定的 1688 原图，不等待八张生成图。商品提交成功后，工作台记录 Seller API `task_id` 和 `offer_id`，并写入图片任务包。

## 7. 图片任务

首次开始前，先把用户提供的 R2 公网地址保存到工作台。例如：

```powershell
$body = @{ base_url = "https://你的-R2-公网域名" } | ConvertTo-Json
Invoke-RestMethod -Method Post `
  -Uri "http://127.0.0.1:8765/api/settings/public-media" `
  -ContentType "application/json" `
  -Body $body
```

当前默认 bucket 为 `yandex-media`，也可通过环境变量
`OZON_V2_R2_BUCKET` 覆盖。Wrangler 必须已登录到能访问该 bucket 的
Cloudflare 账号。只保存域名不代表通道可用；总控还会执行真实 bucket
预检，未通过时不会领取任务或调用生图。

在 Codex 中使用：

```text
$ozon-image-generation-controller
```

总控只负责固定任务箱和十个固定可见任务槽位：

- `ozon-image-worker-01` 至 `ozon-image-worker-10`。
- 十是全局并发上限，不是批次上限。
- 30 或 100 件商品会持续复用这十个槽位直到队列清空。
- 新商品、继续和返修都复用旧任务；除非用户明确要求，不创建新任务。
- 第一次使用且固定任务注册表为空时，用户直接要求开始、继续或处理生图，即授权总控一次性创建并登记缺少的固定槽位；无需再输入固定确认口令。
- 首次初始化中断时只补齐缺失编号。已经登记的固定任务永久不可用、需要替换时，才要求用户明确授权重开对应槽位。
- 一件商品失败或等待人工返修，不阻塞其他商品。

每个可见任务使用 `$ozon-product-media-generator`：

- 锁定一张真实白底主体。
- 将 Ozon 参考图逐张分类为主视觉、生活场景、功能信息图、结构标注、步骤说明、材质特写、尺寸适配、对比或套装陈列，再一对一学习其主体比例、裁切、可见卖点、标题对齐、标注几何、信息密度和留白；只替换背景不算完成模仿。
- 固定使用 `2+3+3` 结构：一个 1×2 主图网格生成 2 张主图，两个 1×3 附图网格生成 6 张附图，全部严格 3:4。
- 生成前先用锁定的 1688 SKU 证据制作一张白底主体锚点；该锚点只锁定产品身份、结构、颜色、数量和比例，不作为最终图库图片。
- 三个成品网格统一加载仓库内固定的高端俄文商业信息图核心提示词；每张图片只表达一个核心主题，产品约占画面 55%—70%。
- 八张图至少覆盖六种布局原型；同一参考图最多用于两个不同买家问题。
- 俄文标签必须在第一次场景生成时自然融入画面：3—7 个俄语单词的标题、不超过 14 个俄语单词的副标题和 2—4 个功能标签；不先生成空图再额外生图贴字。
- 参考图不足或不可解码时，缺少的槽位使用不同的 Ozon 审美兜底原型继续生成，不因缺参考图停止。
- 真实商品事实只能来自锁定 SKU/供应商证据，不能由生成图反推。
- 八张图验收后在本地合成 `slideshow.mp4`，以 `main_01` 生成
  `video_cover.jpg`，不额外消耗生图调用。
- 图片、视频和封面均发布到同一 R2 通道；随后替换 Ozon 图库并提交当前
  Seller API 类目模板暴露的视频字段。
- Ozon 接受图库和视频字段提交后才把任务标记完成；视频仍可能进入 Ozon
  的异步审核。

## 8. 人工处理原则

- 缺供应商：补采或替换该商品。
- SKU 不明确：重新采集 SKU，或对页面唯一 SKU 使用直接锁定。
- 字段缺真实事实：补充用户证据或保留缺口。
- Seller API 字典不匹配：重新获取精确字典值，不上传近似值。
- 图片不合格：只返修选中的槽位，不重做已验收图片。
- 一个商品被阻塞：其余通过门禁的商品继续。

## 9. 明确禁止的自动动作

除非用户在对应页面明确确认：

- 不自动提交商品。
- 不自动最终审批。
- 不使用生成图作为商品属性事实。
- 不绕过真实 SKU、字段、字典、图片或价格门禁。
- 不把密钥写进图片任务包或 Git。
