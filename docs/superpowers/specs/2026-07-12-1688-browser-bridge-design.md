# 1688 浏览器桥接采集设计 (1688 Browser Bridge Collection Design)

日期 (Date): 2026-07-12

状态 (Status): 用户已批准实施 (Approved For Implementation)

## 问题 (Problem)

当前正式供应商 worker 会启动新的无头 Edge。即使用户在正常 Edge 中已登录 1688，新上下文也没有登录态，因此商品链接会被重定向到淘宝登录页，最终只能得到登录页标题和图片，无法通过供应商公开字段验收。

## 设计 (Design)

1. 工作台在 `supplier_collecting` 阶段发布 `browser_task.supplier_collection_ready`。
2. 已安装的 Ozon V2 浏览器扩展接收任务，在用户当前 Edge 会话中打开或复用一个 1688 商品标签页。
3. 1688 内容脚本只采集用户已核实链接的公开字段：标题、卖家、单一 SKU 证据、图片、价格、属性和国内运费证据。
4. 内容脚本把结果提交给工作台；工作台验收成功后自动继续批次。
5. 遇到淘宝/1688 登录页时保持任务阻塞并显示登录门禁，不提交伪结果。
6. 正式工作台不再调用无登录态的无头供应商 worker；旧实现文件保留，不删除、不扩散改动。

## 边界 (Boundaries)

- 1688 始终直连，不使用 Ozon 代理。
- 不自动搜索供应商；只采集用户提交并核实的 1688 商品链接。
- 不改 Ozon 采集、生图或上传模块。
- 一个浏览器任务只维护一个受控标签页，轮询不得反复弹新窗口。
- 只有后端验收并保存 `supplier_collection_result.json` 才算供应商采集成功。

## 验证 (Verification)

- 服务端测试覆盖 supplier browser task 契约与结果接收后自动续跑。
- Node 测试覆盖 1688 任务识别、正常标签页复用和内容脚本字段契约。
- 当前批次 `wb-e3da92000610` 必须使用原链接恢复，且不能再采到登录页素材。
