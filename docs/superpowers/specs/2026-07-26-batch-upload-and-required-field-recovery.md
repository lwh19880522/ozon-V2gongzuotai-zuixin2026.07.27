# Ozon V2 批量上传与必填字段恢复设计

## 目标

上传工作区必须让多件商品并行完成校验和逐件上传，同时对错误类目模板自动重匹配，并只把仍然缺失的必填字段交给用户补录。任一商品失败不得阻塞其他商品。

## 根因

1. 单件预览调用 `build_upload_draft(run_id)`，每次都重建整批草稿并重复解析整批字典字段，商品越多等待越久。
2. 页面只有单件按钮，没有批量调度器；并行点击还会让多个请求竞争写入同一份预览/提交 JSON。
3. 类目可信度检查能发现错配，但上传准备只显示一个手动刷新按钮，没有在批量准备时执行自愈。
4. 缺失必填字段只有红字，没有独立的用户事实入口；让用户继续运行字段 Skill 也无法补出本来就需要人工确认的事实。

## 设计

### 服务层

- 草稿构建支持指定商品过滤。单件预览只解析目标商品；批量协调器对选中商品执行有界并发校验，避免用户逐件等待。
- 批量准备先识别错配类目，使用冻结的 Ozon 标题、类型和公开类目证据重新解析 Seller API 模板；成功后重载工作区。
- 对仍缺失的必填字段返回结构化输入定义：字段 ID、俄文标签、类型、单位、字典信息和允许值。
- 用户补录单独保存为 `required_attribute_evidence.json`，带 `user_confirmed_required_attribute` 来源；只接受当前正确模板中仍然缺失的必填字段。
- 批量上传以一次显式用户确认为授权，按最多 4 个并发商品分别调用 Seller API；每件独立产生 task、提交记录和图片任务包。文件持久化集中在批量协调器中，避免并发读改写覆盖。

### 页面

- 上传门禁增加“批量校验并上传可用商品”按钮；点击后显示一次明确确认，再自动处理当前所有尚未成功的商品。
- 每件商品实时显示：类目重匹配、等待必填补录、校验中、上传中、Ozon 处理中、成功或失败。
- 商品卡只在“必填且未映射”时显示输入框与“保存必填证据”按钮；可选字段保持只读。
- 错类目不显示旧模板必填输入，先自动或手动完成类目重匹配。
- 保留原有单件预览和单件确认作为精细操作入口。

### 生图 Skill 固定任务池

- 固定生图任务注册表为空时，用户直接要求开始、继续或处理 Ozon 生图，即授权执行一次任务池初始化；不再要求用户重复输入固定口令。
- 首次初始化只创建缺失的固定槽位并持久化注册；中断后继续补齐缺失编号，已存在槽位不重复创建。
- 初始化完成后始终复用固定任务。只有已经登记的固定任务永久不可用、确需替换时，才要求用户明确授权创建新任务。

## 边界与安全

- 批量动作不跨商品复用确认令牌，不做全有或全无回滚。
- 已成功或正在处理的商品幂等跳过。
- 测试只使用 Fake Seller API，不执行真实上传、发布或最终审批。

## 验收

1. 单件预览不再为其他商品解析字典。
2. 批量操作一次可并发处理多件，单件失败不影响其他商品。
3. 错类目在上传准备时自动替换为可信模板；无法可信匹配时保持阻塞。
4. 用户只能补录当前模板的缺失必填项，保存后工作区立即重新计算门禁。
5. 页面提供批量按钮、逐件状态及必填输入区。
