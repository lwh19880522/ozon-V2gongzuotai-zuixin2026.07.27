# Ozon V2 俄文边缘渐隐视觉系统设计

## 状态与范围

- 日期：2026-07-21
- 状态：用户已确认 B「边缘渐隐信息系统」，进入实施
- 范围：Ozon V2 本地俄文排版器、媒体生成技能合同、固定测试与离线预览
- 边界：不触发真实生图、采集、上传或最终审批；不修改队列、浏览器采集和 SKU 决策流程

## 问题根因

现有 `integrated_rail`、`context_caption` 和 `feature_callout` 都把俄文放进独立圆角矩形，文字层与场景之间形成清晰的“后贴卡片”边界。`_draw_fact` 还会把标题强制转成全大写，使俄文语气和画面节奏更加生硬。只调整字号、圆角或单张图位置不能解决这个结构问题。

## 已确认方案

三种配方共享一套 B 系统，不再绘制独立信息卡：

1. `integrated_rail` / `metric_panel`：从指定画面边缘向场景内部自然淡出的深色渐变。标题和说明直接落在渐变区域，渐变宽度随文字内容和画布尺寸自适应。
2. `context_caption`：从画面底部向上淡出的深色渐变。俄文沿底部安全区排版，不使用悬浮条或圆角框。
3. `feature_callout`：从结构锚点出发的强调色细线与端点，连接到相对边缘的文字。文字侧仅使用柔和边缘渐变保证可读性，不使用白色说明卡。

`clean_hero` 保持原图不加文字。所有配方继续使用相同的强调色、字族、安全边距和移动端可读性门槛。

## 俄文层级

- 标题保持调用方提供的自然俄文大小写，不再强制全大写；标准缩写可由文案本身保留大写。
- 标题仍是第一信息焦点，说明文字是第二层级。
- 每个事实块继续遵守最多五个标题词和九个说明词的短文案合同。
- 360 像素预览中最小正文仍不得低于 13 像素。
- 只渲染引用锁定供应商证据的俄文事实；数字仍要求 `numeric_verified=true`。

## 自适应规则

- 渐变使用连续透明度而非硬边矩形，靠近画面边缘最深，向主体方向衰减至透明。
- 文字始终位于 Ozon 安全边距内；内容高度超过配方上限时拒绝渲染，而不是缩小到不可读。
- `panel_side` 继续明确主信息位于左侧或右侧；结构标注根据锚点自动使用相对边缘，降低遮挡锚定结构的概率。
- 两个结构标注继续使用独立垂直通道，防止重叠。
- 输出收据增加视觉系统标识，便于区分 B 系统与旧圆角卡片渲染结果。

## 技能合同

图片模型只负责无文字场景，并为相应配方保留自然的边缘或底部信息空间。本地 `render-visual` 负责全部俄文、渐变和锚定线。俄文排版失败只重做本地文字层，不增加图片生成调用。

## 验收

- 三种有文字配方均不调用 `rounded_rectangle`。
- 侧边渐变、底部渐变和结构锚定线可由固定像素测试证明存在。
- 自然大小写保持不变，俄文不会被强制转成全大写。
- 移动端字号、安全区、事实来源、数字和短文案校验继续生效。
- 离线预览只读取现有图片或本地固定夹具，不调用图片模型。
- 图像专项测试和全量 `pytest` 通过后才允许提交。
