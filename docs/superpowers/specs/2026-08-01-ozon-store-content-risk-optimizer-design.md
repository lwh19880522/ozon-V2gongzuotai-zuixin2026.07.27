# Ozon 店铺内容与风险自动优化技能设计

## 目标

新增独立 Codex 技能 `ozon-store-content-risk-optimizer`，自动优化店铺商品的非媒体内容，并在写回和恢复库存前完成事实、语言、价格与合规风险检查。

技能是 Ozon 工作台的配套能力，但不增加工作台页面，不进入现有批次流程，也不重复实现生图。

## 范围与边界

- 优化标题、搜索表达、Seller API 属性、描述和 Rich Content。
- 客户可见内容只能使用自然、准确的俄语。
- 禁止中文、乱码、1688 店铺或供应商信息、批发、代发、包邮及工厂宣传话术。
- 图片和视频不生成、不修改、不上传、不删除；媒体分完全排除。
- 已有图片可只读用于颜色、数量、套装和主体一致性检查；没有图片不扣分、不阻塞，也不得据此猜测。
- 归档商品默认跳过。只有明确的恢复指令才能重新处理归档商品。
- 流量、点击和低效商品归档不属于本阶段。

## 小型实现结构

只新增以下必要文件，不建立新框架：

```text
skills/ozon-store-content-risk-optimizer/
  SKILL.md
  agents/openai.yaml
  scripts/store_content_optimizer.py
  references/optimization-policy.md
```

`SKILL.md` 定义 Codex 工作流；单个脚本负责 Seller API 读取、状态账本、确定性校验、写回、库存和回读；一份规则文件保存字段质量与风险门禁。复用现有凭证、Seller API 适配习惯和字段证据优先级，不修改工作台 UI。

## 持久化与增量执行

账本保存在：

```text
OzonOpsV2/store_content_optimizer/<store-key>/optimizer.sqlite3
```

`store-key` 必须按店铺隔离且不得暴露 API 密钥。每件商品仅保存必要状态：商品 ID、SKU、offer ID、内容指纹、规则版本、状态、风险摘要、写回回执和检查时间。

- 新店铺首次运行：检查全部未归档商品。
- 后续运行：只处理新商品、内容指纹变化、上次中断或待处理商品。
- 已完成且内容未变化：跳过，不重新生成或写回。
- 已发现但未修复风险：保留为待处理，不重复生成相同分析；内容变化或明确复查时再运行。
- 规则升级：只重检受新规则影响的商品。
- 中断：从最近安全状态继续。

## 自动执行流程

1. 读取店铺未归档商品并计算内容指纹。
2. 对照账本选择本次需要处理的商品。
3. 读取官方内容分、类目模板、允许值、当前线上字段、可用工作台证据和锁定供应商 SKU。
4. 只读检查已有图片；没有图片则记录无视觉证据。
5. 生成完整俄语优化稿。
6. 运行确定性校验和 Codex 语义自检，失败字段自动重写。
7. 严重风险能被证据明确修正时先修正；无法安全修正时将 FBS 库存设为 0 并暂停销售。
8. 自动写回内容，随后回读 Seller API 和可访问的公开商品页。
9. 只重试未生效字段；平台异步处理时等待回读，不把“请求已接受”视为完成。
10. 验证通过后：
    - 已在售商品保持现有库存，不覆盖；
    - 当前不处于 `IN_SALE`、库存为 0 或待供货的商品，将 FBS 库存设置为 10；
    - 归档商品不恢复、不补库存。
11. 保存结果和动作回执。

库存动作前必须再次检查商品状态和进行中订单，避免竞态。

## 内容优化质量门禁

- 标题以准确商品词为核心，保留已证实的型号、规格、数量和用途。
- 禁止关键词堆砌、重复词、机械翻译、模板化废话和无法证明的宣传。
- 描述和 Rich Content 使用真实卖点、场景、使用方式、规格、套装组成与注意事项，不重复灌水。
- 有销售价值且证据充分的可选属性应填写；不适用字段不得为凑分填写。
- 词典属性必须使用 Seller API 允许值。
- 单位只能做精确换算，必须保留数字所描述的对象，禁止尺寸与件数串位。
- 客户可见字段写回前必须通过俄语检测和供应商信息清洗。
- Rich Content 必须通过 JSON 结构校验。

官方媒体组不参与成功判断。技能将“文本描述”和“其他属性”两个非媒体评分组按动态权重归一化为 100 分，并以证据允许的最高非媒体分为目标，绝不为满分猜填。

## 风险门禁

检查以下风险：

- 商品身份：标题、型号、颜色、规格和锁定 SKU 冲突。
- 数量套装：销售单位、件数、包装数和套装组成串位。
- 数字单位：尺寸、重量、容量、功率、电压和适用范围错位。
- 类目属性：类目、商品类型、属性 ID 或词典值不匹配。
- 文本语言：中文、乱码、供应商话术、词不达意、关键词堆砌和矛盾描述。
- 图片一致性：已有图片与标题、颜色、数量或套装不一致。
- 前后台一致性：Seller API 与公开商品页的高风险字段不一致。
- 价格：有可靠成本与最低利润证据时检查亏损；无证据时不擅自改价。
- 合规：认证、质保、标识、安全和兼容性不得猜测，无法证明的高风险声明必须删除或暂停商品。

严重风险直接暂停销售；高风险先自动修复，失败则暂停；中低风险自动优化并记录。暂停采用 FBS 库存归零，不自动归档。

## 缺少供应商证据

找不到工作台证据或锁定供应商 SKU 时：

- 只优化能够由 Seller API 当前内容明确证明的语言字段；
- 数量、规格、材质、兼容性等客观属性保持不变；
- 不补库存 10；
- 记录 `evidence_insufficient`，不向用户索取简单字段，也不猜填。

## 回滚与失败处理

- 写回前保存原值和内容指纹。
- 限流时自动降速和退避。
- 部分成功时只重试未生效字段。
- 回读发现中文、供应商信息、数字错位、俄语质量下降或非媒体分降低时自动恢复原值。
- 无法恢复时将库存归零并保存故障回执。
- 相同内容和相同动作不得重复提交。

## 测试与验收

最小测试集覆盖：

- 非媒体评分归一化及媒体分剔除；
- 中文、乱码和供应商信息拦截；
- 俄语标题、描述和 Rich Content 结构；
- 数量、套装、尺寸、重量、功率与单位串位；
- 内容指纹、断点续跑和重复执行保护；
- 严重风险库存归零及安全商品补库存 10；
- 归档商品跳过；
- 缺少供应商证据时不改客观属性、不补库存；
- Seller API 限流、异步更新、部分失败和订单竞态；
- 技能不生成、修改、上传或删除任何图片或视频。

验收要求：同一未变化商品重复运行不产生写请求；安全商品自动完成优化和回读；无法解决的严重风险不继续销售；所有动作可从账本审计和恢复。
