# Ozon V2 工具台一键启动与运行控制设计 (One-click Workbench Launcher And Runtime Control Design)

## 1. 目标 (Goal)

让用户通过桌面上的单一入口快速启动 Ozon V2 工具台，并在工具台内部完成运行状态查看、重启、停止和诊断。正常启动、停止和重启必须快速、可预测，不再依赖 Codex 会话，也不得因旧 PID 文件阻断启动。

## 2. 已确认决策 (Confirmed Decisions)

- 使用现有浏览器工具台，不建设 WebView2 或其他桌面外壳。
- 桌面只保留一个 Ozon V2 工具台入口。
- 不建设安装器，不复制或安装另一份工具台代码。
- 不安装 Windows 服务，不设置开机自启，不保留停止后的常驻控制器。
- 停止后整个工具台服务退出；再次使用时由桌面入口启动。
- 运行控制使用独立、可拖动、可吸附边缘的悬浮胶囊栏。
- 胶囊栏常驻显示本地服务、Edge 扩展和当前任务三个状态。
- 视觉采用石墨黑与翡翠绿色运行状态，展开后显示详细状态、重启、停止和诊断入口。
- 验证期间不得触发真实生图。

## 3. 范围与非目标 (Scope And Non-goals)

### 范围

- 修复并收敛 Windows 工具台生命周期脚本。
- 增加一个轻量桌面启动入口。
- 增加运行状态、重启和停止的本地 API。
- 在全部工具台页面挂载统一悬浮运行控制栏。
- 增加聚焦测试与无真实生图回归验证。

### 非目标

- 不修改旧插件。
- 不建设通用安装程序、自动更新器、托盘应用或 Windows 服务。
- 不建设无限重试或后台守护循环。
- 不自动重启、重载或关闭用户的 Edge 主进程。
- 不把扩展没有发送的心跳伪装成在线。
- 不改变采集、生图、上传或发布业务规则。

## 4. 总体架构 (Architecture)

```text
桌面快捷方式
  -> 轻量启动器 (Launcher)
      -> 健康检查
      -> 工具台生命周期脚本 (Start/Status/Restart/Stop)
      -> 隐藏启动 Python 工具台服务
      -> 健康后打开正常 Edge 工具台地址

工具台页面
  -> 悬浮运行控制栏
      -> 本地服务状态
      -> Edge 扩展心跳状态
      -> 当前任务状态
      -> 重启 / 停止 / 诊断
```

启动器和生命周期脚本是短生命周期进程。工具台停止后不保留新的后台控制进程。

## 5. 桌面一键启动 (Desktop One-click Launch)

桌面快捷方式指向项目内的轻量启动脚本。创建快捷方式只是本机入口配置，不安装或复制工具台程序。

启动流程：

1. 对 `http://127.0.0.1:8765/api/health` 执行最多约两秒的健康检查。
2. 如果服务健康，直接打开正常 Edge 用户配置中的工具台地址。
3. 如果服务未运行，读取项目内运行状态并核验 PID。
4. 只清理已确认失效的运行记录；不得根据未核验 PID 杀进程。
5. 使用隐藏窗口启动工具台 Python 服务。
6. 健康检查成功后打开 `http://127.0.0.1:8765/`。
7. 启动超时或端口冲突时不打开 Edge，只显示简短错误和日志路径。

启动器不得创建临时 Edge 用户配置，不得使用 `--load-extension`，也不得终止用户的 Edge 主进程。

## 6. 运行状态与文件 (Runtime State And Files)

生命周期文件集中放入项目目录：

```text
runtime/workbench/
  workbench.json
  launcher.log
  lifecycle.log
  restart-status.json
```

`workbench.json` 至少记录 PID、端口、项目根目录、启动时间和生命周期状态。写入使用原子替换，避免半写文件。

旧的工作区外 PID 文件不再作为正式控制依据。首次迁移时只读取它用于兼容诊断；无法安全删除时也不得阻断新状态文件的使用。

## 7. 重启与停止 (Restart And Stop)

### 重启

1. 页面调用本地重启 API。
2. 服务启动短生命周期重启辅助进程，并返回“已安排重启”。
3. 页面进入“正在重启”状态并轮询健康接口。
4. 当前服务安全退出。
5. 辅助进程等待端口释放，调用同一生命周期脚本启动新服务。
6. 健康恢复后页面自动刷新；失败时保留错误状态和日志。

重启失败最多补试一次，禁止无限重启循环。

### 停止

1. 用户第一次点击“停止”时，按钮原位变为“确认停止”。
2. 确认后服务先返回停止确认，再安全关闭 HTTP 服务和进程。
3. 页面显示停止完成状态；服务不再自动恢复。
4. 下次启动使用桌面快捷方式。

重复停止必须幂等，不得因状态文件缺失或已停止而报破坏性错误。

## 8. 悬浮运行控制栏 (Movable Runtime Capsule)

控制栏独立于业务导航，挂载在全部工具台页面。

### 收起状态

- 默认位于页面右上角。
- 同时显示“服务、扩展、任务”三个状态。
- 支持拖动、边缘吸附和位置记忆。
- 不允许拖出浏览器可视区域。

### 展开状态

- 本地服务：正常、重启中、停止中、离线或失败。
- Edge 扩展：最近心跳时间、在线、等待或离线。
- 当前任务：空闲、运行、阻塞、停止或失败。
- 操作：重启、停止、重新检测、打开运行诊断。

### 视觉与反馈

- 石墨黑半透明表面，翡翠绿色表示正常运行。
- 琥珀色表示等待、阻塞或重新检测。
- 红色表示离线或失败。
- 灰色表示未启动或无任务。
- 点击页面空白处或按 `Esc` 收起。
- 重启和停止进度在控制栏内部显示，不弹大型模态框。

控制栏位置保存于当前浏览器的本地页面状态；非法或过期位置在页面尺寸变化后自动归位。

## 9. 状态来源与真实性 (State Sources And Truthfulness)

- 本地服务状态来自实时健康接口，不只依赖 PID 文件。
- Edge 扩展状态来自真实桥接心跳和版本门禁。
- 当前任务状态来自工具台现有运行器与活动任务状态。
- 没有真实扩展心跳时必须显示离线或等待，不得因版本匹配而显示在线。
- 工具台服务完全断开时，浏览器页面只能显示连接失败；由于已确认不保留常驻控制器，重新启动必须使用桌面入口。

## 10. 错误处理 (Error Handling)

- 失效 PID：安全忽略或替换，不阻断启动。
- PID 指向未知进程：不得终止，显示明确诊断。
- 端口被非工具台程序占用：不得终止占用者，启动失败并记录端口冲突。
- Python 不可用：显示可执行文件解析失败和修复提示。
- 启动超时：不打开 Edge，保留生命周期日志。
- 重启超时：停止自动补试，显示日志入口。
- 扩展离线：先重新检测；仍离线时显示实际心跳时间和人工处理入口。
- 状态接口失败：控制栏进入红色离线状态，不显示伪成功。

## 11. 测试设计 (Testing)

### 生命周期测试

- 首次启动返回成功并通过 `health.ok`。
- 重复启动复用健康服务，不创建重复进程。
- 失效 PID 文件不会阻断启动。
- PID 指向非工具台进程时拒绝停止。
- 端口被未知进程占用时拒绝误杀。
- 停止后进程退出、端口释放、状态更新。
- 重启后旧进程退出、新服务健康、状态文件更新。
- 重复停止保持幂等。

### API 与界面测试

- 运行状态 API 返回服务、扩展和任务三类真实状态。
- 页面包含可拖动胶囊栏、三点状态和展开操作。
- 停止具有原位二次确认。
- 重启过程展示中间状态并在恢复后刷新。
- 扩展心跳过期时显示离线。
- 位置记忆和视口边界逻辑可测试。

### 验证边界

- 测试不得打开真实 Ozon 或 1688 采集页面。
- 测试不得调用真实生图工具。
- 测试不得启动临时 Edge 配置或强制加载扩展。

## 12. 验收标准 (Acceptance Criteria)

- 用户双击单一桌面入口即可打开健康工具台。
- 正常启动、停止和重启不显示命令窗口。
- 重复启动不产生重复服务。
- 旧 PID 或外部旧状态不会再次卡住启动。
- 悬浮栏在所有工具台页面一致、美观、可拖动、可收起。
- 三项状态均来自真实数据。
- 重启和停止操作快速、清晰且不会误杀其他进程。
- 停止后不保留新增常驻控制器。
- 全部聚焦测试和相关回归测试通过，且未生成真实图片。
