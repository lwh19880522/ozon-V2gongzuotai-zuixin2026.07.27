# Ozon 受管 1688 通道覆盖采集恢复设计

## 背景与根因

Ozon V2 的 `supplier_content.js` 已经实现受管 1688 页面固定卡片，包含“采集当前商品”和“找不到供应商”。卡片只在当前标签能通过后台取得受管通道绑定时显示。

现有后台在任一受管标签关闭后，会把同一任务的所有 `channels[].tabId` 一次性清空，并调用整批停止接口。其余仍然打开的 1688 页面因此失去通道身份，内容脚本会把它们视为普通页面并撤掉固定卡片。这正是用户截图中没有采集按钮的直接原因。

## 目标

1. 受管 1688 页面始终按通道显示固定采集卡；普通 1688 页面仍不显示。
2. 用户关闭单个通道标签时，只让该通道进入待恢复状态，不暂停整批、不解绑其他通道。
3. 用户关闭整个受管窗口时，仍按既有规则暂停整批。
4. 工作台明确重启产生新 dispatch token 后，只补开缺失且未完成的通道，健康通道保持原标签、原页面和原绑定。
5. 原生 Ctrl/Shift/中键打开的新标签继续受到保护；扩展接管搜索结果或详情页时先原子迁移绑定，再关闭旧页，不产生误取消。
6. 用户点击采集后，回传并持久化当前 1688 商品的 URL、标题、商家、图片、价格、国内运费、原始属性、SKU 分组和可提取的 SKU 组合；只有工作台确认保存成功后才把通道标记为已完成。
7. 已有 Ozon 原产品属性字段自动采集和工作台重启入口保持不变，不把 Ozon 原字段和 1688 供应商字段混为同一负载。

## 状态与边界

### 单通道关闭

后台按 `tabId` 找到唯一通道，仅执行：

- 将该通道 `tabId` 设为 `null`；
- 非终态通道保持 `waiting_user`，并记录 `closedAt`；
- 将任务窗口状态标为 `incomplete`；
- 保存绑定表。

它不得清空其他通道、不得设置整任务 `closedByUser`、不得调用 `/runner/stop`。

### 整个窗口关闭

`chrome.windows.onRemoved` 仍负责整批暂停：清空窗口内全部通道标签绑定、设置 `closedByUser` 和当前 dispatch token，并调用 `/runner/stop`。同一个 token 不得自动重开。

### 明确重启

新 dispatch 到达且受管窗口仍存在时，以 `(channel_index, seed_id, ozon_product_id)` 为稳定身份对齐通道：

- 身份相同且旧 `tabId` 仍存活：原样保留；
- 身份相同但标签已关闭：只在现有受管窗口创建一个新标签；
- 不按当前窗口标签数组顺序猜测通道；
- 不导航、不重载健康标签；
- 只向当前任务中的绑定标签注入或刷新采集卡。

同一个 dispatch token 的后台轮询只保留 `incomplete`，不会自动补开用户关闭的标签；补开必须来自工作台的明确重启。

## 字段回传

固定卡的用户点击是同款确认动作。提交负载沿用现有 `supplier_product`，至少锁定：

- `supplier_url` / `final_url` / `offer_id`
- `title` / `seller`
- `images` / `price` / `domestic_shipping_evidence`
- `attributes`
- `sku_groups` / `sku_options`

服务端以受管通道的 `channel_index + seed_id + ozon_product_id` 校验归属，保存完整商品对象，再返回 `accepted=true` 与 `lane_terminal=collected`。内容脚本只有收到该成功回执后才禁用按钮并发送通道终态消息。

## 验证

所有验证只使用本地 JS VM 和临时仓库：

- 五通道关闭其中一个后，其他四个 `tabId` 和绑定不变，且没有整批停止请求；
- 同 token 不自动补开；新 token 只创建一个缺失标签，健康标签不导航、不重映射；
- 扩展接管子标签关闭旧页时不触发暂停；
- 覆盖按钮提交属性与 SKU 字段，服务端保存后字段不丢失；
- 普通页面不显示受管采集卡；
- 完整 pytest 回归通过。

不触发真实采集、生图、上传、发布或最终审批。
