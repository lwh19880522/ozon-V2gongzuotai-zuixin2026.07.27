## 阻断问题 (Blocking Issues)

### OZV2-001 后台执行器存在状态竞态 (Runner State Race)

- 优先级：P0
- 状态：已修复 (Resolved)
- 证据：增加运行中人工动作门禁并隔离发布锁测试；40 次重复测试失败 0 次，HTTP 测试 15 项通过。
- 根因：创建批次后后台线程立即运行；HTTP 人工动作和测试可以同时修改同一份 `run.json`。`FsRepo.save_run()` 没有版本检查，执行器也没有持久化租约，旧线程可能覆盖新状态。
- 影响：状态回退、按钮结果与页面状态不一致，停止后仍可能出现迟到写入。
- 修复方向：增加执行器取消探针和单批次运行门禁；人工动作在执行器运行时必须拒绝或先安全停止；发布门禁测试与自动执行测试隔离。

### OZV2-002 停止动作不是硬边界 (Stop Is Not A Hard Boundary)

- 优先级：P0
- 状态：已修复 (Resolved)
- 证据：`run_until_blocked()` 在每次自动迁移前检查停止探针；后台线程停止回归测试确认线程真实退出，且 `runner.stopped` 后无迟到的 `runner.blocked`。
- 影响：用户点击停止后，当前自动循环仍可能完成后续状态写入。
- 修复方向：调度器每次状态转换前检查取消信号；停止后不得创建新浏览器任务，迟到结果不得自动恢复流水线。

### OZV2-003 Seller 精准类目模板匹配失败 (Seller Category Template Match Failure)

- 优先级：P0
- 状态：修复待实战复验 (Fix Implemented, Live Recheck Pending)
- 证据：批次 `wb-fe5bee73618b`、`wb-cff6ef01586f` 和 `wb-baf68008ab0e` 均记录 `attribute_template.seller_schema_unavailable`。检查真实 Seller API 树发现旧解析器得到 0 个节点。
- 根因：Seller API 把 `description_category_id` 放在父类目节点、`type_id` 放在子类型节点；旧解析器错误地要求两者位于同一节点。类目匹配还误用了会删除空格的商品去重归一化，导致词级评分失效。
- 影响：没有真实 `description_category_id`、`type_id` 和必填属性模板，后续草稿无法准确构建。
- 已实施：子类型继承父 `description_category_id`；类目文本保留词边界；支持有限俄语词尾变化；商品标题作为高权重证据；低于中等置信度仍拒绝。
- 验证：真实 Seller API 将“Ценник крафтовый...”匹配为 `Канцелярские товары / Оборудование для торговли / Ценник`，`description_category_id=71328593`、`type_id=970615927`、属性 31 个、必填 3 个，置信度 high、得分 100。Python 全量 93 项通过。
- 剩余：让现有浏览器会话重新回传后确认工作台状态实际进入下一门禁；后续再增加确定性映射缓存和人工校正复用。

### OZV2-004 自动化只实现到 Ozon 采集门口 (Pipeline Stops After Ozon)

- 优先级：P0

- 修复方向：按模块化设计分阶段接入供应商链接门禁、生图执行器和上传执行器。

### OZV2-015 种子池俄语查询词覆盖不完整 (Seed Query Coverage Incomplete)

- 优先级：P0
- 状态：已修复 (Resolved)
- 证据：新增 96 个种子精确俄语查询映射；整包 500 种子覆盖测试逐项调用现有安全校验，缺失项为 0。
- 根因：所谓自动查询词生成器是有限的本地关键词字典，不是覆盖全部种子的确定性查询词包；系统又把未命中字典视为人工输入门禁。
- 影响：每次随机抽种子约有 19.2% 的种子可能阻断批次，目标数量越大越容易整批停住。
- 修复方向：在随插件发布的种子包中为全部 500 个种子预生成并校验安全俄语查询词；运行时只读取已验证词，不临时依赖人工翻译。启动批次前检查目标种子查询词完整性，不完整时换用其他未用种子并记录数据错误。

### OZV2-016 扩展后台自动开页被主动禁用 (Extension Auto-Start Disabled)

- 优先级：P0
- 状态：已修复 (Resolved)
- 证据：扩展 `0.1.6` 在任务到达时自动创建或复用 Ozon 标签；同一任务重复消息不创建、不重导航，下一阶段复用原标签并只导航一次；旧批次无任务时自动回退领取最新活动任务，Node 行为测试通过。
- 根因：为解决重复弹窗，旧修复把后台自动开页完全禁止，导致自动化被一起关闭。
- 影响：即使查询词和采集合同已经准备好，没有现成 Ozon 标签页或用户点击扩展时也不会启动采集。
- 修复方向：改为每个任务键只允许创建一个受控标签页；新任务自动创建或复用，重复轮询不得重复开页。停止任务后禁止恢复，下一新任务才能重新取得标签页租约。

### OZV2-007 浏览器重复开页缺少回归证明 (Browser Tab Reuse Regression Gap)

### OZV2-017 已完成批次继续认领历史任务 (Completed Run Claims Historical Task)

- 优先级：P0
- 状态：已修复，待实战复验 (Resolved, Live Recheck Pending)
- 根因：扩展保存着当前批次 ID 时，如果该批次已经完成，后台曾回退到按目录修改时间选择的“最新活动任务”，从而接着认领历史批次；随后修复又把当前批次锁得过死，导致创建时间更晚的新批次也无法被自动接走。
- 影响：目标数量为 1 的批次完成后，浏览器仍连续跳转多个商品，看起来像同一批次失控。
- 修复：服务端严格按批次 `created_at` 选择最新批次，不再使用目录修改时间。扩展在当前批次结束后只接创建时间更晚的新批次；更早的历史任务继续拒绝。
- 验证：Node 行为测试覆盖历史任务拒绝、新批次自动接单和单次标签导航；服务端测试覆盖旧目录后来被修改也不得超越新批次。

### OZV2-018 本土店商品被误当成海外店商品 (Local Product Accepted As Cross-Border)

- 优先级：P0
- 状态：已修复，待实战复验 (Resolved, Live Recheck Pending)
- 证据：批次 `wb-129957bef2a9` 技术上记录了 `ozon_collection.ingested`，但商品为俄罗斯本土店，卖家判断置信度为 `unknown`，不符合业务要求。
- 根因：旧采集器记录了卖家证据，但入库验证器没有强制要求“中国跨境店高置信证据”。
- 修复：浏览器端逐个检查候选；只接受高置信的中国发货、Ozon Global 中国专区或中国企业主体证据。本土仓、证据未知和仅标注中国制造均不放行。服务端对同一规则再次硬校验。
- 结论：旧批次属于“技术入库成功、业务验收失败”，不得作为有效采集结果继续使用。

### OZV2-019 目标数量没有精确约束 (Target Count Not Exact)

### OZV2-020 扩展升级后旧标签未重新注入脚本 (Stale Tab After Extension Upgrade)

### OZV2-021 海外店证据范围过宽且无法复盘 (Cross-Border Evidence Scope And Audit Gap)

- 验证：新增无关中国文本、本土仓冲突、远距离 Ozon Global 文本、精准种子词和候选拒绝事件测试；全量 99 项通过。

### OZV2-022 商品详情未加载完成就执行海外店判断 (Seller Evidence Checked Before Render)
